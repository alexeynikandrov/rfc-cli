## Problem

Сейчас `rfc-cli` доступен AI-клиентам только через запуск shell-команд и
разбор текстового вывода. Это требует от каждого клиента знать CLI-синтаксис и
формат таблиц, а также не даёт стандартного интерфейса Model Context Protocol.

## Goal

Добавить подкоманду `rfc-cli mcp`, которая предоставляет read-only операции с
RFC как MCP tools через локальный `stdio`-транспорт. Существующий CLI остаётся
основным пользовательским интерфейсом.

## Requirements

1. Команда `rfc-cli mcp` запускает MCP-сервер через `stdio`.
2. Сервер поддерживает JSON-RPC 2.0 и принимает как newline-delimited JSON,
   так и сообщения с заголовком `Content-Length`.
3. Сервер не пишет обычные логи в stdout, чтобы не загрязнять MCP-транспорт.
4. Сервер реализует MCP lifecycle:
   - `initialize`;
   - `notifications/initialized`;
   - `ping`;
   - `tools/list`;
   - `tools/call`.
5. В первой версии доступны read-only tools:
   - `ping`;
   - `list_rfcs` с необязательным фильтром `status`;
   - `view_rfc` с аргументом `number`;
   - `get_rfc_status` с аргументом `number`;
   - `get_rfc_dependencies` с аргументами `number` и `reverse`.
6. Результаты tools возвращаются как JSON-объекты в `structuredContent` и как
   JSON-текст в `content`.
7. Некорректные аргументы возвращают JSON-RPC ошибку `-32602`, неизвестный
   метод — `-32601`, внутренние ошибки — `-32603`.
8. MCP tools используют те же RFC-файлы и индекс, что и обычные команды, но
   read-only операции не должны изменять `.index.json`.
9. `rfc-cli init` создаёт или обновляет запись `rfc-cli` в `.mcp.json`,
   сохраняя другие MCP-серверы:

   ```json
   {
     "mcpServers": {
       "rfc-cli": {
         "command": "rfc-cli",
         "args": ["mcp"]
       }
     }
   }
   ```

## Design

### CLI

Добавить подкоманду:

```rust
/// Run MCP server over stdio
Mcp
```

`main.rs` передаёт в MCP-сервер уже определённый `project_root`, поэтому MCP и
CLI используют одинаковое разрешение `RFC_HOME`.

### MCP frontend

Новый модуль `src/commands/mcp.rs` содержит:

- stdio reader/writer;
- JSON-RPC dispatch;
- MCP tool schemas;
- преобразование ошибок в JSON-RPC;
- read-only обработчики tools.

Обработчики напрямую используют `rfclib::index` и `rfclib::rfc`, не запускают
другие CLI-команды и не парсят их человекочитаемый stdout.

### MCP configuration

`init` читает существующий `.mcp.json`, проверяет, что корень документа и
`mcpServers` являются JSON-объектами, добавляет запись `rfc-cli` и сохраняет
остальные записи без изменений. Повторный запуск идемпотентен.

## Alternatives

1. **Оставить только shell-вызовы CLI**  
   Не требует изменений, но сохраняет привязку клиентов к текстовому выводу.

2. **Добавить MCP через отдельный прокси-проект**  
   Усложняет установку и может привести к расхождению поведения с `rfc-cli`.

3. **Сразу добавить изменяющие tools**  
   Увеличивает риск случайной модификации RFC через AI-клиента. Изменяющие
   операции можно добавить отдельным RFC после подтверждения схемы разрешений.

## Voting

Открытые вопросы для review:

1. Достаточен ли read-only набор tools для первой версии?
2. Нужны ли resources в следующей версии?
3. Нужны ли изменяющие tools после отдельного согласования безопасности?

## Migration

Миграция RFC-файлов и индекса не требуется. После обновления достаточно
запустить `rfc-cli init`, чтобы добавить запись сервера в `.mcp.json`. Старые
конфигурации MCP и существующие CLI-команды не изменяются.
